01 • ARQUITETURA & TECNOLOGIAS

Monólito Modular & Stack Tecnológica

Arquitetura: Monólito Modular

  • Next.js 14 (App Router) + TypeScript: Frontend e API REST unificados, sem complexidade de rede ou microserviços desnecessários.
  • Fronteiras de Domínio Claras: Módulos encapsulados (auth, projects, tasks, metrics) que facilitam a atuação do agente sem quebrar contexto.
  • Prisma ORM + SQLite: Esquema relacional estrito, migrações automatizadas e seed idempotente no arranque.
  • Segurança & Sessão: Cookies HTTP-only com tokens HMAC-SHA256 e palavras-passe em hash bcryptjs.

Tecnologias & Operações

  • UI & Interação: React 18, Tailwind CSS, @hello-pangea/dnd para Kanban e Recharts para velocidade semanal.
  • Validação de Contratos: Schemas estritos com Zod em todos os endpoints de mutação.
  • Docker Multi-Stage: Construção em 4 estágios com base Alpine Linux (~250MB de runtime) e utilizador não-root.
  • Deploy em Produção: Alojado como Web Service Docker no Render.com com certificado SSL automático e HTTPS.
02 • METODOLOGIA AGÊNTICA COM IA

Governança Rigorosa com AGENTS.md

Regras Imperativas de Conduta (AGENTS.md)

  • Princípio Plan-First: O agente detalha objetivos e ficheiros antes de executar qualquer edição em larga escala.
  • Controlo Estrito de Escopo: Implementação restrita ao MVP, sem inventar funcionalidades fora do roadmap sem aprovação prévia.
  • Menor Alteração Necessária: Edições cirúrgicas nas linhas estritamente necessárias, sem refatorações destrutivas.
  • Tolerância Zero a Ações Destrutivas: Bloqueio autónomo de comandos como drop table ou git reset --hard sem confirmação humana.

Garantia da Qualidade por BDD

  • Especificação em BDD: Todas as User Stories formalizadas com critérios Given / When / Then em docs/user-stories.md.
  • Pirâmide de Testes Automatizada: 10 suites cobrindo validação de título (13/13), integração API & SQLite (33/33), segurança IDOR (21/21) e MVP formal (34/34).
  • Testes como Âncora de Verdade: O agente de IA só considera uma tarefa concluída após execução e aprovação empírica de 100% dos testes.
03 • RESILIÊNCIA & RESOLUÇÃO DE PROBLEMAS

Desafios Técnicos & Soluções Aplicadas

⚠️ 1. Runner Node 20 & Execução TypeScript

Problema: Os testes falhavam no GitHub Actions com ERR_UNKNOWN_FILE_EXTENSION no Node 20 LTS.

Solução: Integração de tsx nas dependências de desenvolvimento, permitindo execução universal e tipada direta sem compilação prévia.

⚠️ 2. Padrão OCI & Trivy Scanner

Problema: O Trivy falhava com o erro fatal could not parse reference devido às maiúsculas no username (luisAfonsoM).

Solução: Normalização estrita do namespace da imagem para minúsculas (luisafonsom/matriz-ai-course), cumprindo a especificação OCI.

⚠️ 3. SQLite & Migrações em Contentor

Problema: O contentor parava no arranque do smoke test com falta de DATABASE_URL no prisma migrate deploy.

Solução: Definição de fallbacks seguros no Dockerfile e injeção declarativa no script docker-entrypoint.sh.

⚠️ 4. Segurança RBAC & Mitigação de IDOR

Problema: Risco de desassociação indevida de utilizadores por membros de equipa na rota PUT /api/v1/tasks/:id.

Solução: Barreira defensiva na camada da API com validação da sessão e bloqueio estrito com HTTP 403 Forbidden.
