01 • VISÃO DO PRODUTO & CASO DE USO

Equilíbrio entre Agilidade de Execução e Controlo

01

O Desafio Operacional

Equipas distribuídas frequentemente perdem visibilidade sobre o estado real das entregas, acumulando atrasos não detetados e duplicação de tarefas por falta de rastreio colaborativo transparente.

  • Falta de clareza na atribuição de múltiplos intervenientes.
  • Dificuldade em detetar tarefas críticas fora do prazo UTC.
  • Inexistência de indicadores de velocidade da equipa.
02

A Solução Matriz

Uma aplicação web unificada que centraliza o ciclo de vida dos projetos, combinando um quadro Kanban intuitivo com cálculo em tempo real de KPIs de produtividade.

  • Fluxo visual de tarefas: TODO ➔ IN PROGRESS ➔ DONE.
  • Comentários contextuais e histórico de auditoria.
  • Métricas dinâmicas ponderadas e velocidade semanal.
03

Perfis de Utilizador (RBAC)

Distinção clara de privilégios para garantir integridade e governação dos dados da organização:

  • Gestor de Projeto (PM): Criação/eliminação de projetos, alteração de datas limite, relatórios executivos.
  • Membro de Equipa: Transição fluida de cartões Kanban, registo de comentários, auto-atribuição de trabalho.

03 • DECISÕES ARQUITETURAIS

Arquitetura de Monólito Modular

Porquê Monólito Modular vs Microserviços?

Para um PoC ágil no contexto do curso, microserviços introduziriam overhead de orquestração de rede desnecessário. O Monólito Modular proporciona:

  • Processo Unificado: Frontend React e rotas de API REST servidos no mesmo runtime Next.js 14, sem problemas de CORS.
  • Fronteiras de Domínio Rígidas: Separação limpa entre auth, projects, tasks e metrics.
  • Contexto Otimizado para IA: O agente de codificação opera em módulos delimitados, reduzindo o consumo de tokens e prevenindo alucinações.
  • Portabilidade Zero-Setup (RNF05): Corre de imediato com um único comando em qualquer computador.

Estrutura em Camadas do Sistema

1. CAMADA DE APRESENTAÇÃO (UI / React 18)
App Router, Tailwind CSS, Componentes Kanban, Dashboard & Modais
2. CAMADA DE APLICAÇÃO & API (Next.js Routes)
Autenticação HMAC-SHA256, RBAC, Validação com Schemas Zod
3. CAMADA DE PERSISTÊNCIA (Prisma ORM + SQLite)
Modelos tipados em schema.prisma, migrações e seed automático
4. OPERAÇÕES & CI/CD (Docker Compose & GitHub Actions)
Imagem multi-stage Alpine, scans Trivy e publicação automática GHCR

05 • METODOLOGIA DE DESENVOLVIMENTO

Engenharia Guiada por Agentes de IA

Governança Rigorosa com AGENTS.md

Para evitar alucinações, introdução de dívida técnica ou desvios de escopo, definimos regras imperativas para o agente de IA:

  • Consulta Obrigatória de Contexto: Consulta sistemática de requirements.md, user-stories.md e constraints.md antes de qualquer edição.
  • Princípio Plan-First: O agente apresenta obrigatoriamente um plano prévio detalhado com ficheiros impactados e aguarda validação humana.
  • Menor Alteração Necessária: Edições cirúrgicas nas linhas necessárias, sem refatorações destrutivas ou estilísticas alheias ao pedido.
  • Tolerância Zero a Ações Destrutivas: Proibição expressa de comandos como drop table, git reset --hard ou remoção de ficheiros sem confirmação.

3. Implementação e Testes Imediatos
Codificação modular seguida da execução de suites unitárias e de integração.
4. Verificação Empírica & Commit
Nenhum código é promovido sem passar 100% dos testes e typecheck.

09 • LIÇÕES DE ENGENHARIA & RESILIÊNCIA

Principais Desafios Encontrados & Soluções

⚠️ Desafio 1: Runner Node 20 & TypeScript

Problema: Os ficheiros de teste .ts falhavam na pipeline do GitHub Actions com o erro ERR_UNKNOWN_FILE_EXTENSION no Node 20 LTS.

Solução: Adicionámos o runtime tsx às devDependencies, permitindo execução universal e tipada de todos os scripts sem necessidade de compilação prévia.

⚠️ Desafio 2: Especificação OCI e Trivy

Problema: O Trivy falhou na pipeline com o erro fatal could not parse reference devido ao facto de o username do GitHub conter maiúsculas (luisAfonsoM).

Solução: Normalizámos declarativamente o namespace da imagem no Docker metadata e no Trivy para minúsculas estritas (luisafonsom/matriz-ai-course), respeitando o standard OCI.

⚠️ Desafio 3: SQLite no Smoke Test do Docker

Problema: O contentor parava no arranque do smoke test com P1012: Environment variable not found: DATABASE_URL.

Solução: Configurámos valores seguros por omissão no Dockerfile e passámos as variáveis de ambiente explícitas no comando docker run do workflow.

⚠️ Desafio 4: Resolução de Vulnerabilidade IDOR

Problema: Risco de um membro de equipa desassociar colegas ou alterar tarefas que não lhe pertenciam via API direta.

Solução: Reforço defensivo na rota PUT /api/v1/tasks/:id com verificação da sessão e bloqueio estrito com HTTP 403 Forbidden.
